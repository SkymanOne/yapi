# Differences from Pi

yapi follows Pi `v1.0.0` and behaves like Pi except as listed here. Any other difference is a bug. Please [report it](https://github.com/SkymanOne/yapi/issues). The tables cover extensions, packages and installation, the interface and providers, and tools and sessions, each with Pi's behavior, yapi's, and the reason.

yapi's tests use Pi itself as the reference. End-to-end scenarios compare yapi with output recorded from Pi: terminal screens, JSON event streams, print mode runs and remote procedure call (RPC) sessions. Settings, credentials and session files round-trip byte for byte. [Extensions](extensions.md#compatibility-with-pi) has the extension and package results.

## Extension runtime and API

Pi extensions run unchanged, in WebAssembly rather than Node.js. These rows cover where their runtime and API differ:

| Area | Pi | yapi |
|---|---|---|
| Runtime | Pi's Node.js process | QuickJS-NG in WebAssembly: 60s of computing per call and 10s while loading, 1 GiB per instance, restart after a crash. See [How the extension sandbox works](security.md#how-the-extension-sandbox-works). |
| Node APIs | All of Node | [Shims](extensions.md#how-pi-extensions-run). Sockets, servers, `http` requests, `worker_threads`, `node:sqlite`, `zlib`, `vm` and `child_process.fork` throw when used. `require()` of an ES module fails. |
| Native addons | Loaded | Installed, never built. Loading one fails. |
| Pi internals | Every export of Pi's packages | The extension API and its helpers. The other exports of `pi-agent-core` and `pi-coding-agent` behave as in Pi, except those listed under agent sessions and under Pi internals that bypass the host. `pi-ai` has its own row. Built-in tool factories return yapi's tools, or Pi's own when given custom `operations`, a `spawnHook` or a `commandPrefix`. |
| `pi-ai` exports | Pi's `pi-ai` | Pi's own `pi-ai` code, with yapi's providers behind its wire APIs and its OpenRouter image generation. These make their requests in yapi, so they don't use a `fetch` option. Some exports throw when called, by design. `createModels`, `builtinModels`, `builtinProviders`, the built-in provider factories such as `anthropicProvider`, `cloudflareAIGatewayAuth`, `cloudflareWorkersAIAuth`, `defaultProviderAuthContext` and `findEnvKeys` would resolve provider credentials inside the runtime that every JavaScript extension shares, outside the host's checked credential requests. `setBedrockProviderModule` and `registerImagesApiProvider` would let one extension replace code that receives other extensions' credentials. |
| Agent sessions in an extension | `createAgentSession` and Pi's SDK | Not supported, by design. `AgentSession`, `AgentSessionRuntime`, `createAgentSession`, `createAgentSessionFromServices`, `createAgentSessionRuntime`, `createAgentSessionServices`, `ModelRegistry`, `ModelRuntime`, `DefaultResourceLoader`, `DefaultPackageManager`, `ExtensionRunner`, `createExtensionRuntime`, `discoverAndLoadExtensions`, `main`, `runPrintMode`, `runRpcMode` and `InteractiveMode` throw when called. They run a second Pi agent inside the extension, with its own model runtime and credentials, extensions loaded by jiti, which needs Node, and packages installed by npm. Pi's modes would also take over the terminal and the output that yapi owns. `createMcpExtension` throws too, as yapi's Model Context Protocol (MCP) client is built in. Run a subagent as another yapi, with Pi's `RpcClient` or as Pi's `subagent` example does. `pi-agent-core`'s `Agent` and agent loop work, over the stream function and tools the extension gives them. |
| Pi internals that bypass the host | Every export of Pi's packages | Not supported, by design. An extension reaches credentials, project trust, settings and sessions only through the host, which checks its grants, so these throw when called. `readStoredCredential` would hand it the raw keys and refresh tokens in `auth.json`. `ProjectTrustStore` would let it trust a project without you, so the project's extensions and settings load at the next start. `SettingsManager` would let it rewrite `settings.json`, such as the shell, the npm command, packages, extension paths and the default project trust. `SessionManager` would let it write and rewrite session files, and `SessionSelectorComponent` deletes them. The `grep` and `find` tool factories refuse custom `operations`, because Pi's tools then download ripgrep and fd into the agent folder's `bin`, which yapi adds to every command's `PATH`. |
| Extension UI | Components detect links, images and theme changes | Links and images fall back to text. Theme changes reach extensions at their next session. `getAllThemes` gives the built-in themes no path, as they are built into yapi. |
| `pi.events` | Every listener runs during `emit`, in the order of subscription | Listeners in the emitter's runtime instance run during `emit`. Native extensions and other instances get the event after `emit` returns, as a JSON copy, and data JSON can't carry stays in the emitter's instance. An instance that is busy holds at most 64 events from others and drops later ones until it catches up. |
| Terminal input listeners | Pi handles each key before the next one reaches them | They run while yapi keeps drawing, so keys that arrive together pass through them together. |
| Focused component | `tui.focusedComponent` is the component that has the keyboard | The extension's own editor when it replaced yapi's. Otherwise a stand-in, as yapi's editor, selectors and dialogs aren't objects in the runtime: an `Editor` with no state while the prompt editor has the keyboard, and an empty object while a selector, a dialog or a component has it. |
| Autocomplete providers | The editor waits for providers | yapi's editor never waits: `applyCompletion` runs for every suggestion, and `signal` never aborts. Editors from `setEditorComponent` behave as in Pi. |
| `newSession` setup | `setup` gets the new session's whole `SessionManager` | It reads the session and writes with `appendMessage`, `appendCustomEntry` and `appendSessionInfo`. Other writes throw. |
| Failing session actions | A throwing `setup` or `withSession` callback ends interactive mode | yapi reports the error and keeps the current session. |
| Console output | stdout and stderr | stderr only in print, JSON and RPC modes, because stdout carries their output. Interactive mode keeps it off the screen, and `/debug` writes its last 200 lines. |
| Clipboard | `copyToClipboard` writes its Operating System Command (OSC) 52 fallback to stdout in every mode | Only in interactive mode. In print, JSON and RPC modes stdout carries their output. |
| `ctx.modelRegistry.getProvider` | The pi-ai `Provider` itself | Its id, name, models, `stream` and `streamSimple`. yapi's built-in providers aren't JavaScript objects, and an extension's `Provider` stays in the runtime instance that registered it. |
| Project trust | Extensions loaded before trust can answer `project_trust` | No extension loads before you trust the project. |
| [Codemode](mcp.md#call-mcp-tools-through-codemode) scripts | May compute without limit | Stop after 60s of computing without awaiting a call. |
| Model availability of extension providers | `getAvailableOfType` runs a pi-ai `Provider`'s API key `check`, `filterModels` and `filterAllModels` on each call | `getAvailableOfType` returns what they kept at the last refresh. They run in the extension's runtime instance as extensions load, on `/login`, `/logout` and `--api-key`, when the model selector opens, on `/reload`, on `ctx.modelRegistry.refresh` and after an extension registers or unregisters a provider. The host answers model queries from codemode and extensions without calling into a runtime instance, so a busy instance never blocks them. |
| Native extensions | None | WebAssembly components written in Rust. See [Write native extensions in Rust](native-extensions.md). Unstable until 1.0. |

## Packages and installation

yapi installs Pi's packages with its own client and keeps its own folders:

| Area | Pi | yapi |
|---|---|---|
| Folders | `~/.pi/agent`, project `.pi/`, `PI_CODING_AGENT_DIR` | `~/.yapi/agent`, project `.yapi/`, `YAPI_CODING_AGENT_DIR`, and `YAPI_` in place of `PI_` for the session directory variable. Same formats, and `yapi import pi` copies Pi's state. |
| Package installs | `npm install`, with lifecycle scripts | A built-in npm client that skips lifecycle scripts. `npmCommand` applies to npm sources only. Its output always goes to stderr and it reads no input, where Pi does this only when stdout carries JSON or RPC output. |
| Git sources | A host or ref may start with `-` | yapi refuses a host or ref that starts with `-`, because git would read it as an option. Clones run as `git clone -- <repo>`. |
| Sign-ins after `yapi import pi` | Pi keeps its sign-ins in its own `auth.json` and `mcp-auth.json` | `yapi import pi` copies API keys but not subscription or MCP sign-ins, and lists the ones it left out. A provider can replace its refresh token on each use, so one shared copy would sign the other tool out. Sign in again with `/login` or `/mcp login`. |
| Packages that fail to install | Pi exits at startup, and `/reload` or the session change fails | yapi warns at startup and lists the package under `[Extension issues]` after `/reload` or a session change, which try it again. It runs without the package, so one unreachable source doesn't stop the others. |
| npm configuration | npm reads all its configuration files and settings | Registries, credentials and `fetch-timeout` from `~/.npmrc`, or the file `npm_config_userconfig` names, and from `npm_config_*` variables. yapi ignores other settings, such as `cafile`. |
| Log file | `/debug` writes `pi-debug.log` | `--enable-logging`, a yapi-only flag, also appends a running log to `yapi.log` in the agent folder. See [Read yapi's log](troubleshooting.md#read-yapis-log). |
| Project folder | The working folder | `--project-dir <dir>`, a yapi-only flag, takes the project's files, trust and `AGENTS.md` from another folder while tools run in the working folder. Subagents need it to work in one folder with their parent's project. See [Project trust](security.md#project-trust). |
| Project packages | No counterpart | yapi also ships `chest`, a separate binary with a manifest and lock for skills, subagents and extensions, and capabilities granted per extension. `yapi install` and the `packages` of `settings.json` work as in Pi. See [Get started with chest](chest.md). |
| Package manifests | The `pi` key | For each kind of resource, a list in the `[package]` table of the package's `chest.toml` wins, then a list in a `yapi` key of the same shape, then the `pi` key. One package can ship a native build for yapi, and a package without `package.json` loads from `chest.toml`. A `yapi` key or `[package]` table that lists no resources, such as one holding only `capabilities`, hides nothing. See [Package manifests](packages.md#package-manifests). |
| Self-update | `pi update` updates Pi | `yapi update` prints how to upgrade instead. `--extensions` and `--models` update packages and model catalogs. The update notice takes the version from yapi's latest GitHub release and links the releases page as the changelog. Pi's release note has no counterpart. See [Upgrade yapi](install.md#upgrade-yapi). |
| `new` | `pi new ...` is a prompt | `yapi new` creates a native extension. Quote a prompt that starts with `new`. |

## Interface and providers

These rows cover the terminal interface, links and images, and provider requests:

| Area | Pi | yapi |
|---|---|---|
| `/share` | Shares a session through Pi's services | Not available. |
| Name given to other programs | Requests carry `User-Agent: pi (<platform> <release>; <arch>)`, and commands run with `AI_AGENT=pi` | Requests carry `User-Agent: yapi/<version> (<os>; <arch>)`, and commands run with `AI_AGENT=yapi`, so servers and tools can tell yapi from Pi. |
| `/bug` | Uploads a private report to Pi's service at radius.pi.dev, or exports it as a zip file | Always writes the zip file to the working folder, then offers to post a public issue on [SkymanOne/yapi](https://github.com/SkymanOne/yapi/issues) with the GitHub CLI. The report has no crash log. Its diagnostics come from the current branch, and its `session.jsonl` holds the branch without Pi's system prompt and tool list. The session records the report as a `yapi.bug-report` entry. |
| Clipboard paste | Copied files, images and text on every platform | Nothing on Windows, and images copied in Windows don't reach Windows Subsystem for Linux (WSL). |
| Word motions in Chinese, Japanese and Thai | By dictionary word | By character, to keep the dictionaries of International Components for Unicode (ICU) out of the binary. |
| Time zones | Node's own time zone data | The system's time zone database. With `TZ` set to a zone name on a system without one, times show in UTC. On Windows they show in UTC unless `TZ` holds a POSIX rule such as `EST5EDT`. |
| Links | A click in fullscreen mode opens any link in its default app. Link URLs reach the terminal as written. | A click opens only `http`, `https` and `mailto` links, and shows a linked file in its folder. Opening a link to a script or an app, or with another scheme, could run a program. A link whose URL holds a control character shows as plain text, because the character could end the link and reach the terminal as a command. |
| MCP sign-in page | Opens the authorization endpoint an MCP server names with any scheme but `javascript`, `data` and `vbscript` | Opens only `http` and `https` endpoints and fails the sign-in on another scheme. The page opens without a click, and another scheme could launch an app or run a program. |
| Syntax highlighting | Highlights code in messages and tool rows | Shows code in one color, to keep memory use and install size low. Extensions can add highlighting with [`pi.yapi.registerCodeRenderer`](extensions.md#code-renderers). |
| Markdown transformers | Change a message's Markdown before it shows | A message shows as written in its first frame, and each change while it streams shows transformed one frame late. |
| Images in the terminal | A Herdr pane shows images when the outer terminal's variables reach it, such as Ghostty's. Image data reaches the terminal as written. | A Herdr pane shows Kitty images in any terminal, as Herdr draws them itself. An image whose data isn't base64 shows as a note, because such data could reach the terminal as a command. |
| Mouse in fullscreen mode | Extension editors and components get mouse events. | Extension headers, message renderers and tool renderers get no mouse events. Other extension components get presses, clicks and the wheel, but no pointer moves, drags or releases, and a click doesn't give them the keyboard focus. |

## Tools and sessions

These rows cover tool arguments, file edits, sorting and session files:

| Area | Pi | yapi |
|---|---|---|
| Deeply nested tool arguments | Tool-call arguments parse at any depth | Arguments nested more than 512 levels deep read as `{}`, so a model's output can't crash yapi with a stack overflow. |
| `write` and `edit` arguments that aren't strings | A `tool_call` handler can change the arguments after validation. The tool then fails with whatever Node error comes up, such as `Cannot read properties of undefined (reading 'replace')`, after `write` creates the parent folders. `edit` of a missing file reports the missing file first. | The tool fails with `The "<name>" argument must be of type string.` before it touches the path or the file, so the message is clear and the tool creates or changes nothing. |
| Sorting names | ICU's `localeCompare` sorts every script | Latin letters, accents and marks sort as ICU's root collation does. Letters of other scripts sort by code point, to keep ICU's data out of the binary. |
| `edit` on a file that isn't UTF-8 | Reads it as UTF-8 and writes every invalid byte back as U+FFFD | Refuses the edit with "File is not valid UTF-8.", so bytes outside the edit never change. |
| Line endings after `edit` | The whole file takes the line ending of its first line break | Lines the edit leaves unchanged keep their own line endings. Changed lines take the ending of the first line break. |
| Session lines with an unpaired surrogate | Pi writes text cut inside an emoji as an unpaired UTF-16 escape, such as `\ud83d` | The line loads with U+FFFD in place of the unpaired half, as Rust strings can't hold one. |
| Failed session writes | Later entries can point to an entry that is missing from the file | yapi reports the first failed write and saves the missed entries with the next write, so the history stays whole. |
| Fractions in count settings | A fraction such as `1.5` in `retry.maxRetries`, `retry.baseDelayMs`, `thinkingBudgets`, `editorPaddingX` or a similar count reaches the code that uses it unchanged | yapi rounds the fraction down, since yapi counts retries, milliseconds, tokens and cells in whole numbers. Whole numbers written as floats, such as `1.5e5`, read as in Pi, and Pi's own rounding of `terminal.imageWidthCells` and its checks of the `compaction` token settings apply as in Pi. |
